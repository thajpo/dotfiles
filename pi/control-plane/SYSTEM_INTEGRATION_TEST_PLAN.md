# Pi System Integration Test Plan

The system tests use disposable HOME, state, data, cache, runtime, and Git
roots. They invoke the exact staged or installed executable and never contact
a remote model provider.

Required journeys:

1. Register two repositories and prove identity, isolation, unchanged
   historical sentinel files, and unmanaged-work visibility.
2. Start secretary and read-only investigators; prove scoped read, forbidden
   tools, completion, failure, needs-user, interruption, and durable results.
3. Create two workstreams; prove distinct working copies, branches, containers,
   writer generations, and package environments.
4. Exercise worker messages, exact host/container-network requests, approval
   replay rejection, dependency review, exact revision review, fast-forward,
   integration, restart, fault recovery, presentation, staging, and rollback.

The acceptance runner must record evidence outside the repository and fail on
help-only, syntax-only, fabricated Docker, skipped, or unobservable actions.
